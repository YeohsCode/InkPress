# 图文编辑：先写成文章，再设计页面

## 参考过的开源实现

这些项目用于研究排版方法。本项目仍由 HTML / Playwright 出图，没有声称接入它们的引擎。

| 项目 | 实际查看的实现 | 本项目采用的原则 |
| --- | --- | --- |
| [Paged.js](https://pagedjs.org/en/documentation/5-web-design-for-print/) | 命名页面、页面尺寸、页边距、分页与出血的文档 | 封面与正文页使用不同的页面角色；一页的版式服务于该页内容 |
| [Vivliostyle samples](https://github.com/vivliostyle/vivliostyle_doc/tree/gh-pages/samples) | `adaptive-layout/apollo8/style.css`、`webmag/css/viv-style-h.css`、`news/style.scss` | 图与文字分别进入页面区域；大图、引文、正文的字级分开，长标题与图版不能用同一种规则处理 |
| [Ghost Source](https://github.com/TryGhost/Source) | `assets/css/screen.css` 的 `gh-canvas` / `kg-width-wide` / `kg-width-full`，以及 `post.hbs` | 正文宽度、宽图、通栏图是不同层次；照片不必被塞进正文的一栏 |
| [Postext magazine cookbook](https://postext.dev/en/cookbook/magazine-three-column-feature) | 六页样例的预览与完整排版代码 | 开场大图、跨栏图片、文字页与收尾之间形成节奏；栏目数量不等于版式设计 |

## 页面的决定顺序

1. 先写出连续读得通的文章，再按论点、场景或证据变化分页。不要先规定每页三段，再找文字填满。
2. 为各页标注阅读任务：开场、解释、观察、比较、数据、争议、停顿、结尾。
3. 为图片标注用途：报道照片、作者原图、可核查的数据重绘、机制示意、概念插画。说明图片解释了什么。插画可以建立气氛和意象，不能充当实验结果。
4. 写页面计划 `design.style: "editorial"`；每页选择合适的 `design.layout`。明确计划先于视觉类型的通用回退，避免所有带图页又被送进同一模板。
5. 让图幅、字级、行长与密度共同变化。可用通栏大图、图上标题、单栏、局部左右关系、原图图版、数据主视觉和纯文字页。不要机械轮换，也不要整套都用左右双栏。
6. 截图后逐页看。检查标题的落点和对比度、主体是否被裁掉、是否需要跨栏、读图顺序、正文行长、重叠与孤字。联系图检查节奏，单页放大检查细节。

`editorial_layouts.js` 提供 cover / atlas / plate / maps / process / data / source / essay / closing 页面角色。
`editorial_figures.js` 画关系图与数据条形图。原始图表始终 contain；概念插画可以裁切和有意叠字。
若内容不适配现有角色，调整布局或新增角色，不能把所有页面降成同一种安全模板。

## 文字：把审美从禁词表里拿回来

新闻和科普的文学品质来自观察、组织和分寸。没有事实的支撑，漂亮的词只是装饰；没有句子的呼吸，正确的事实也会变成说明书。

- **开头有落点。** 从真实变化、具体物件、人物动作或一个可想象的场景进入。补上时间和出处。不能编造记者亲历、受访者说话或实验细节。
- **一个主比喻贯穿。** 比喻帮助读者理解关系，不能每页换一套仓库、搬家、地图的说法。标明一次示意性质即可，不要在每段后插入「这个比喻只是说明」。
- **让句子承接。** 说明新名词以前，先给它一个能被理解的对象；上一段留下的问题，由下一段自然接住。删去提示语之后若出现断裂，就重写整个句群。
- **听节奏。** 一句承担一件事。长句展开关系，短句落下判断；不要把全文砍成同样长的短句，也不刻意把每段写成三句。
- **用名词和动词承载。** 检查「机制、结构、维度、边界、意义」究竟指什么，必要时换成具体对象。删去没有增加事实或感受的形容词。
- **保留事实的分寸。** 证据不足处写清限制，不要在每个例子旁自我辩解。结尾落在事件和证据上，不制造万能金句。

编辑分两遍做：第一遍核对事实、出处、单位与论证；第二遍暂时放下关键词清单，把文章从头读到尾，检查主语、指代、转折和句子长度。禁用格式检查是末端门禁，不能当作改写算法；不要用同义词替换把病句留在原处。自评分不能证明文章已经有品味。

参考阅读：[Orwell, Politics and the English Language](https://www.orwellfoundation.com/the-orwell-foundation/orwell/essays-and-other-works/politics-and-the-english-language/)。这里借鉴的是对陈旧意象和空泛措辞的警惕，不套用其个人文风。

## 本次改写的例子

旧稿：「这里的仓库只是解释概念的例子，并非论文实验。所谓表征相似，关心的是输入经过模型处理后怎样彼此关联。」

新稿：「它像一张地图。坐标可以换，纸张可以转，车站旁边的广场仍在那里。两套数字不必逐项相同，也可能保留相近的结构。」

前者在解释自己的写作动作，后者让具体关系承担解释。图注统一说明示意性质，正文因而可以连贯展开。

## 证据与技术检查

- `visual.kind: "illustration"` 要求真实图片与含「插画」的图注，并限制在 editorial 版式中；数据页仍只接受 bars / source_chart。
- 插画的有意叠字只允许封面艺术区域。刊头、图注不能覆盖原图坐标或数据；检查原图、关系图和文字片段的边界。
- 字号不得低于页面声明的阅读下限。放不下时调整图幅、行长、分页，或正常编辑重写；排版器不能暗中删字。
- 训练样本的图表允许经过明确单位换算核对：图用百万次，正文可写2160万次或9亿次。不能因校验器只会匹配数字原文，就把中文改成拗口的「21.6百万次」。
- 运行 `node --test tests/*.js` 与 `python3 -m unittest discover -s tests -v`。程序通过之后，仍须视觉与全文编辑检查。

## 素材的来源记录

允许使用当前执行环境可用的内置 ImageGen、具有适当使用授权的免费素材、允许相应用途的新闻源配图，以及原始科学图表。可下载不等于有复用许可；无法确认使用条件时选择明确许可的替代素材、自绘或生成插画。

每期保存素材文件、原始页面与图片地址、作者/机构、许可或使用依据、所需署名、裁切改动。生成图保存工具与提示词，并在图注标明插画；不能把生成图当成新闻现场或实验结果。记录可放在期号目录的 `assets/credits.json` 或 `素材与提示词.json`。图幅与素材由报道需要决定，不为填满图片配额而找图，也不因没有原图就把整篇降为文字卡。


## 内容编排与近期对照（2026-11-11）

页面角色不等于构图。新稿设置 `design.planning_version: 1`，每张卡的 design 声明 `layout`、`variant`、`intent`（本页阅读任务）与 `rationale`（为什么这种图幅、顺序、密度适合本页材料）。这些是内部编辑元数据，不印在读者页面上。正文先写通，按事实和论证变化分页，不能把 p4 固定为数字、p5 固定为机制，也不默认九页或固定三段。

当前可用构图（standard 保留原构图）：

| 内容与角色 | variant | 选择依据 |
| --- | --- | --- |
| cover | standard / framed | 现场或气氛大图可出血；需保留主体的产品、概念图用框内图，标题与图片分区 |
| plate | standard / inset | 大幅照片可通栏；原图与需要完整观看的素材留边，不把截图当壁纸 |
| atlas | standard / wide | 竖向图适合局部图文并置；宽图、关系图用通栏，再接正文 |
| process | standard / rail | 短而宽的机制图居中；明确的多步流程可竖向展开，旁边解释，避免每期都用相同的横向关系图 |
| data | standard / ledger | 少量关键比较可突出主数字；多行核查数字用紧凑账表，数值、标签与共用零基线同排 |
| essay | standard / plain / columns | 短引导段可放大；持续叙述用单栏正常字号；适当长度的背景或多方说法可双栏，不能硬塞长段 |
| maps / source / closing | standard | 按关系、原图完整性与真实结尾选择，不必为求变化强换 |

机制示意明确 `visual.layout`：flow 是有先后顺序的过程；views 是两种输入汇合；maps 表示同一组关系的两套坐标；constellation 表示近邻关系。不能把所有机制都画成“同一组关系／另一套坐标”。process:rail 适配 flow；若材料不是流程，不虚构箭头。

写稿前运行 `python3 -m pipeline.core.layout_plan --recent daily`（周报用 `--recent weekly`）查看最近三期同刊的编排。页面计划完成后运行 `python3 -m pipeline.core.layout_plan <report路径>`，逐项复核 REVIEW 提示：相邻同构、连续多期相同位置同构。相同版式可以服务相同内容，但要具体说明本期理由；复核整套标题落点、图幅、疏密、读图顺序，不能靠换色、改名、机械轮换或补无关照片制造差异。

正式投递全部图片和全文成功后，发送器自动保存 `data/layout-history/<date>-<edition>-<hash>.json`，供下一期比较；dry-run、部分投递和本地预览不记录成已送达刊物。历史按 Daily / Weekly 分开。历史缺失时不伪称已对照；旧的作者草稿快照标记 authored-draft，不能当最终成品。

截图验收必须同时看整套与单页；数据单位、比例、原图完整、正文完整和阅读字号继续受原有校验约束。新的构图装不下时，正常编辑或重新分页，不能只为过检改回 standard。
